Connect to `/ws` on the same host as the HTTP API (`wss` with HTTPS). No Telegram login or hub credentials are needed for public market reads. Browser origins must match the application or its configured CORS allowlist.

Send JSON text messages. `subscribe_window` starts a live window of asks or bids; collection and currency are required. Use `/catalog` for IDs and `/collections/{id}` for trait choices. Choose a fresh ID for each operation, including replacements, retries and reconnects. IDs identify both requests and subscriptions; never reuse an active ID. The GUI retains logical names internally and uses unique wire IDs to ignore delayed frames. IDs contain 1–64 ASCII letters, digits, underscores, dots or hyphens. `cancel` releases any request or subscription without an acknowledgement; canceling an unknown or already-completed ID is harmless. Cancellation drops pending work and suppresses queued frames for that operation; frames already sent can still arrive, so clients must ignore canceled IDs. Execution history uses HTTP `/history/query`.

`subscribe_window` is the GUI's live asks/bids interface. Each update replaces **all** rows in one bounded window from one pinned replica view:

```json
{"type":"subscribe_window","id":"window.1","query":{"filters":{"collection_id":"tg.gift.123","currency_id":"GRAM"},"side":"ask","sort":"price_asc","anchor":null,"before":50,"after":99}}
```

`before + after + 1` must be 1..200. A null anchor follows the head; otherwise use a row's opaque `position`. Positions are bound to filters, side and sort, and contain no upstream credentials or retained snapshot IDs. Each `window` frame contains `{id, window: {data, anchor, has_before, has_after, cursor}, sync, revision}`. Data entries have the shared `OrderResponse` fields plus `position`. `anchor` identifies the resolved anchor in this replacement; it is null only for an empty window. The server follows that order's current rank, or chooses its next matching neighbour (previous at the end) when it disappears. It fills available space at either end, and enforces scan, byte, read-admission and cancellation budgets. It never returns a partial window as if it were complete.

To scroll, cancel the previous operation and subscribe with a fresh ID and a visible row's position. Keep the old window on screen until the replacement arrives, then swap it atomically and restore the visible order's pixel offset. The GUI prefetches near both edges, debounces navigation and retains at most one bounded live window. It does not merge pages or fetch `/orders/query` for active live views. A `sync` frame only updates metadata; the server already checked the entire subscribed window. Reconnect using the most recent resolved anchor, rather than restarting at the head. Positions are ordering anchors, not numeric page offsets or total counts.

History retains HTTP snapshot pagination. Paused asks/bids use `POST /orders/window` with `{query: <GiftOrderWindowQuery>, snapshot: null}` to open a frozen view around the visible live anchor. The response is `{window, snapshot, sync, revision}`. Send that opaque `snapshot` on later window reads to keep the same immutable view. Positions are portable between live and frozen reads. `DELETE /orders/window` with `{snapshot}` releases the view; closing or resuming the GUI releases it automatically. Views expire after 60 seconds idle and share the existing 128-view limit. An expired/released view returns `restart_read`; the GUI opens a new snapshot at the current anchor without mixing old and new rows. A release racing a read cannot resurrect its view.

The old `subscribe`, `page` and `unsubscribe` messages are removed. Update consumers together with the API and GUI.

Typed one-shot requests share this connection with subscriptions:

```json
{"type":"request","id":"value.1","method":"valuation.evaluate","params":{"gift":"https://t.me/nft/PlushPepe-123","currency_id":"GRAM"}}
```

`params` is the same `GiftValuationRequest` accepted by `POST /valuations/gift`, including catalog collection/number references. Unknown methods, fields and malformed commands are rejected. The API uses the same handler, actor, validation and public response for both transports. Success is `{"type":"result","id":"value.1","method":"valuation.evaluate","data":<GiftValuationResponse>}`; failure is `{"type":"error","id":"value.1","error":{"code":"not_found","message":"..."}}`, with structured `details` when available. A result or error completes the request and releases its slot. Per-metric valuation issues remain inside a successful report.

The default server request deadline is 30 seconds; expiration returns `timed_out`. The GUI applies a 35-second deadline including connection setup, sends `cancel` on local timeout or AbortSignal cancellation, and rejects requests on transport loss. Closing or changing gift details cancels its valuation. Requests are not queued for reconnect or retried implicitly. Healthy subscriptions continue while requests complete, fail or cancel. No HTTP fallback creates duplicate valuation work. Catalog resources, strategy metadata/documentation, history and frozen continuation pages retain HTTP access.

`window` is an atomic replacement. A `sync` frame only updates metadata for the current window; it never requires HTTP page reconciliation. Snapshot history pages still use `/history/query` and `next_page_token`; `cursor` is a replica checkpoint, not a navigation token.

`command_error` reports a rejected command, for example a duplicate active ID: `{"type":"command_error","id":"value.1","error":{"code":"invalid_query","message":"duplicate operation ID"}}`. It does not terminate or cancel the referenced operation. A typed request completes only with `result` or `error`. Errors with an empty ID describe malformed commands or connection failures.

Server WebSocket pings keep the connection alive; browsers reply automatically. Defaults: 16 subscriptions and 8 concurrent one-shot requests per connection, 64 KiB input JSON, 4 MiB encoded windows, 15-second heartbeats and 35-second idle timeout. Embedded deployments may override these limits. Slow consumers close with code 1013. On disconnection, reconnect with backoff and resubscribe using the same queries; operation IDs belong to each connection. One-shot requests fail on disconnect and are never replayed automatically. The test console reconnects only when you click Connect.

An error with an empty ID applies to the connection or malformed command. Setup/query/encoding errors terminate that subscription; replace or resubmit its ID after correcting the cause. Market freshness can remain stale while the last replicated data is still available. Close code 1001 may indicate shutdown; 1011 indicates an API operation failure.

`watch_catalog` subscribes to catalog content revisions: `{"type":"watch_catalog","id":"catalog","collection_ids":["tg.gift.123"]}`. Watch at most eight collection IDs; an empty list watches only the directory. It shares the same socket, limits and lease lifecycle as order subscriptions. Identical watch lists share computation. Initial subscription and reconnection send a complete `catalog` frame with `versions: {directory, collections: {"tg.gift.123": "revision"}}`; a null collection revision means it is no longer a gift collection. Subsequent frames are sent only when that version set changes. Prices and freshness heartbeats do not emit catalog frames.

Catalog content revisions match the unquoted `ETag` headers of `GET /catalog` and `GET /collections/{id}`. These endpoints accept `If-None-Match` and return 304 for unchanged content. Their JSON bodies remain data-only. Compare revisions to retain unchanged cached entries, reload a changed active collection, and mark changed inactive collections stale until needed. Register a watch for cached and active collections; resubscribe after changing that bounded set. On reconnect, compare the complete current versions against cached ETags to recover missed changes without clearing the whole cache. These revisions describe content, not replica progress or synchronization status.

The GUI handles subscription failures independently: a transient catalog error retries that catalog subscription while healthy order streams continue. Permanent subscription errors are displayed and can be retried explicitly or by changing the watch selection. Transport reconnects and transient retries use bounded exponential backoff with jitter. Catalog HTTP invalidations coalesce behind an in-flight read; a response made obsolete by a newer revision schedules one follow-up for the latest state. Changing collection names or directory summaries does not cancel a choices download for the same collection.
