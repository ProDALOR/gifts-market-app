# market-valuation

Gift valuation actors, calculations, the typed strategy registry and lifecycle ownership. Production dependencies are `market-gifts` for domain contracts and `market-actors` for read-only market access. The crate has no direct hub protocol, replica storage, HTTP or Telegram dependency.

`Service::start_on(&data, id, factory, config)` starts an ordinary Actix actor on the shared `market-data` Arbiter. The factory receives a `MarketReader` and `Lifecycle`. `market-app` supervises the returned task. `MarketDataService::start_actor` is a general service-factory hook; the data actors do not depend on valuation. Actors read shared immutable snapshots, with one bounded heavy-read worker and the common market query budget. No actor owns a full orderbook copy or a dedicated OS thread.

`floors.rs` owns model/collection floor actors and caches. `calculation.rs` validates and normalizes supplied positions once, scans each collection in ascending price order, and assembles portfolio rows and totals. Catalog resolution accepts model lookups and returns neutral identity/label records. Quantities remain in valuation inputs. Each floor actor retains up to 16 normalized portfolios for 30 seconds. Relevant collection/currency books and exact catalog references invalidate marks; unrelated orders and catalog entries preserve them. Name and Telegram alias lookup also tracks the collection directory, because additions can make a lookup ambiguous. Only the requested trait is loaded and tracked; a model valuation does not load backdrop/pattern options. Restricted rules read exact keys. Unrestricted rules page through options while retaining only the requested trait and checking cancellation between pages. Expiry is checked on demand after the cache TTL; floor actors have no periodic scan.

`multipliers.rs` owns model/backdrop multiplier actors. Cache, refresh and calculation policy lives in ordinary private Rust helpers; a small macro generates typed actor/message boilerplate. The actors retain separate typed inputs, outputs and state. Each actor retains up to eight collection/currency statistics sets and its last result mark. A native Actix timer refreshes the last requested book every 30 seconds and clears state after five idle minutes. Other books refresh on demand. Timer preparation uses `ctx.spawn` with one in-flight guard, so cached requests remain responsive during a refresh waiting for worker capacity. A completed older refresh cannot replace a newer prepared state. Request preparation is serialized with native atomic responses; multiplier preparation has a ten-second deadline.

`error.rs` owns `ValuationError`, strategy failure codes and evidence, preserving underlying data errors as their source. Data-layer errors carry no valuation payload. `registry.rs` selects explicit named strategies and enriches valuation failures with request context. API and bot both use this registry. `market-portfolio` supplies grouped inventory positions; it performs no pricing calculation. Public HTTP requests and heterogeneous result types remain gift-oriented. Marks contain `{strategy, data, revision, evaluated_at}`. The duplicate `data.cursor` has been removed; use the mark's `revision`. `sync` remains part of each result's data and describes its source snapshot.

`runtime.rs` contains typed `Evaluate` messages, bounded clients, `Prepared<T>`, `Mark<T>` and lifecycle tasks. `Arc<Mark<T>>` owns its data directly, with one shared allocation. A prepared result records the pinned source revision and preparation time; all marks computed from it retain that timestamp. Admission defaults to 128 queued/running requests and a 30-second caller deadline. Dropping or timing out a caller cancels its request context; the native response future retains its admission permit until it exits. Dropping the task rejects new work and signals shutdown. Unexpected actor exit is reported by `task.run(stop)`; `task.shutdown()` waits for termination. CPU work owns its capacity permits until it exits. Dropping a preparation future or stopping the data service signals cancellation to its snapshot; order scans, catalog paging and lookup loops stop at their next cancellation check. Arbitrary blocking callbacks must cooperate too. The market-data task drains CPU work on shutdown.

Run `CARGO_INCREMENTAL=0 cargo test --locked --offline -p market-valuation` for regression coverage of dependency invalidation, pinned reads, one-pass scans, cache expiry, refresh responsiveness, admission, cancellation and shutdown. Regression tests include a catalog with over 50,000 unrelated options, cancellation between pages and revision checks under worker saturation. Full workspace checks also enforce the dependency direction.

The data capability lives under `market-actors/src/read/`: `catalog.rs`, `orders.rs`, `dependencies.rs` and `execution.rs`. `MarketReader::prepare(callback)` returns `Result<T, DataError>` for the callback's owned `T`; a fallible valuation callback therefore uses `.await??`. Dependency validation first compares scoped book and metadata revisions without walking references. After metadata changes, exact checks run on the bounded worker pool, and successful checks memoize that metadata revision. Cached requests with unchanged revisions need no worker slot. Freshness starts at preparation completion, and is rechecked after asynchronous validation; time spent waiting for validation never renews a cached or newly prepared result.
