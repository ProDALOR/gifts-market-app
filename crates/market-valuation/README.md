# market-valuation

Gift valuation contracts, actors, calculations and lifecycle ownership. Requests, strategy IDs, marks, metrics, evidence and valuation errors live here. Shared gift identities, catalog lookups and lookup failures stay in `market-gifts`. Production reads use `market-replica::ReplicaReader` and the pure `market-gifts-hub` adapter. There is no production dependency on `market-actors`, HTTP or Telegram; data actors are used only in integration tests.

`ValuationHandle::start(&arbiter, reads)` starts the gift actor and target-report coordinator on the application-selected Arbiter. `ValuationTask` supervises and drains both interfaces as one service lifecycle; an unexpected exit stops the other actor. Both actors share one bounded floor cache. `reads` is the shared `market-replica::ReadExecutor`. The application owns `market-replica::ReadRuntime`, supplies its `ReadExecutor` to both data and valuation actors, and drains it after stopping the actor services. Handles cannot close the shared tracker. The generic `Service::start_on(&arbiter, id, factory, config)` accepts a factory receiving `Lifecycle`; callers capture a `ValuationSource` or other inputs in the factory. Actors share immutable replica snapshots; they do not copy full orderbooks or create a thread per strategy.

`types.rs` owns shared gift requests and error metadata; `portfolio/types.rs` owns opt-in portfolio contracts; `gift_floor/result.rs` defines the strategy-owned `GiftFloorValuation` and `GiftFloorEvidence`; its mark is `GiftFloorMark = Mark<GiftFloorValuation>`. Reusable metrics live in `types/metric.rs`. The optional `schema` feature enables OpenAPI metadata. `gift_floor/actor.rs`, `gift_floor/statistics.rs` and `gift_floor/calculation.rs` implement `gift_floor`: collection, model, backdrop and matching model+backdrop floors; dimensionless model/backdrop multipliers; and the final mark. The final mark is `round2(min(matching floor, collection floor * unrounded multipliers))`. Only displayed multipliers and the final mark round to two decimals, using midpoint-to-even. Each metric carries a value or a typed issue. Multipliers require three distinct identifiable gifts for both the collection and selected trait. `ValuationMetric<T>` separates monetary `Amount` values from dimensionless `Multiplier` values while retaining the same decimal-string JSON encoding. Evidence groups `collection`, `model`, `backdrop` and `model_backdrop` each expose `listings` and `gifts`; `minimum_multiplier_gifts` states the threshold. Final errors retain their original code, sample evidence and typed failed `dependency`.

The gift actor retains at most eight collection/currency statistics sets, with at most 20,000 aggregate/known-trait entries per set. Statistics are rebuilt on demand when relevant dependencies change, the earliest eligible ask expires or a five-minute safety age is reached. There is no periodic refresh task. Each preparation has a 30-second read deadline. Gift resolution and all statistics use one pinned view. Short cache locks cover only lookup and publication; validation and scans run outside the lock on read workers. The shared heavy-read lane serializes preparations. Traversal deduplication is bounded to 200,000 identity memberships per scan and releases the identity sets before caching aggregate prices/counts. Cross-listings share identity references during traversal and count once per floor. Broad criteria supply prices but cannot satisfy gift-count thresholds. The Arbiter remains responsive while work waits for capacity.

`portfolio.rs`, `portfolio/floors.rs` and `portfolio/calculation.rs` retain explicit quantity-based portfolio floors behind the opt-in `portfolio` Cargo feature, enabled by `market-portfolio`. Inventory and its Telegram transport remain available for future user portfolio integration. The gift API uses its own error-details projection so portfolio evidence is absent from OpenAPI even when workspace feature unification enables portfolio valuation. Each floor actor caches up to 16 normalized portfolios for 30 seconds. Relevant books and catalog references invalidate marks; unrelated updates preserve them. Name and Telegram lookups also track collection-directory changes that could introduce ambiguity. Restricted catalog rules read exact keys; unrestricted rules retain only the requested attribute while paging. Cached inputs with unchanged revisions need no worker slot. Freshness is rechecked after asynchronous validation; waiting does not renew a cached result.

`source/` owns valuation-specific catalog resolution, gift lookup, eligible asks and dependency checks. Generic bounded catalog paging belongs to `market-replica::catalog_read`, shared with data actors. `ValuationSource::prepare(callback)` returns the callback's result inside an execution result; fallible callbacks use `.await??`. Preparation pins the replica after admission. Snapshot reads, catalog loops and dependency checks cooperate with cancellation.

`ReadExecutor` executes both admitted API/data-actor queries and valuation work with one query budget and one tracker. Data actors retain a separate tracker only for live subscription producers. Heavy preparation is limited to one worker; small metadata checks use shared admission without occupying that lane. Dropping a caller cancels its worker token, which follows live and pinned readers into generic catalog helpers, but permits remain held until blocking work exits. Shutdown rejects new reads, cancels queued work and drains admitted work. Arbitrary blocking callbacks must cooperate with their cancellation token.

`runtime.rs` contains typed messages, bounded clients, `Prepared<T>`, `Mark<T>` and lifecycle tasks. Marks contain `{strategy, data, revision, evaluated_at, stale}`; the source revision stays internal and stale describes delayed updates in the pinned view. Admission defaults to 128 queued/running requests and a 30-second caller deadline; the gift handle limits admission to 32. Dropping or timing out a caller cancels its request context. Dropping the task rejects new work and signals shutdown. Unexpected actor exit is reported by `task.run(stop)`; strategy panics remain failures even during supervisor cancellation; `task.shutdown()` waits for termination. `error.rs` maps replica failures into valuation error codes while retaining the original error as its source.

Run `CARGO_INCREMENTAL=0 cargo test --locked --offline -p market-valuation -p market-replica -p market-actors` for coverage of calculations, cache invalidation, pinned reads, bounded admission, cancellation and shutdown. Workspace dependency-boundary tests enforce the production crate direction separately from test fixtures.

Catalog traversals and order scans share a 2,560-page work budget, in addition to the 50,000-row/key catalog limits and statistics limits. Key chunks share a traversal budget; unmatched options consume it too. Exact catalog lookups read selected collection/model keys without loading unrelated directories. Name/Telegram lookups retain complete-directory ambiguity checks. Gift facts use the pure `market-gifts-hub::concrete_gift` projection, without constructing public order responses.

The strategy-owned `gift_floor/methodology.md` is the user-facing explanation of floors, formulas, sample requirements, rounding and limitations. It is embedded in the same binary as the calculation. The API serves it at `/valuations/strategies/gift_floor/documentation` with content-based ETag revalidation; the GUI loads its Markdown renderer and guide only when the user expands “How is this calculated?” in gift details. Update this file alongside any calculation change.

`StrategyMetadata` is owned by each strategy (`gift_floor::METADATA`). The gift-strategy catalog exposes IDs, names, summaries and Markdown without transport URLs or mixing strategy result types. The API presents it at `GET /valuations/strategies` with `documentation_url` links; documentation routing looks up IDs in the same catalog. Portfolio-only library actors are not advertised as available API strategies.

Use `$...$` for inline LaTeX and `$$...$$` for display formulas in strategy Markdown. The GUI renders these with micromark's math extension and KaTeX, loaded only when a guide opens. Native MathML output keeps formulas accessible, respects the market's existing policy against inline styles and needs no extra math font downloads. Keep HTML and KaTeX trust disabled. The frontend pins one current KaTeX version via an npm override because the math extension's upstream dependency still targets an older release.

Registration is explicit in the gift-strategy catalog. Startup requires the strategy's descriptor to be registered and uses its ID for the actor; application supervision reads the descriptor back from the typed handle. Discovery caches its serialized representation and per-guide ETags once per process. Every public descriptor includes `documentation_revision`, so a Markdown change also changes the discovery ETag.

The GUI requests metadata when the calculation-info popup is opened for a result’s strategy. Shared, bounded resource caching coalesces consumers and cancels work when its last consumer leaves; it is also reused by previews. Metadata is retained for one minute and revalidates on the next use, without polling. An unfamiliar result ID checks a cached catalog once; repeated unknown IDs do not cause a request storm. Rendered guides are retained by URL and documentation revision, within a byte limit, so reopening details does not download and typeset the same formulas again. No singleton catalog entry is inferred as a default strategy.

`ValuationDisplay` is a display projection, not a replacement for a strategy's typed result. `gift_floor/display.rs` selects fields directly from `GiftFloorValuation`: order, labels, primary emphasis, optional attribute placement (`model`, `backdrop`, `pattern`), exact or fixed decimal precision, currency/suffix, summary and note. Attribute placement associates a metric with a gift preview without frontend metric-name matching; ungrouped fields remain visible as general values. Decimal formatting uses checked domain amounts and midpoint-to-even rounding; typed values retain their calculation precision. Shared helpers produce currency, number and unavailable display values, including readable error details. A strategy can construct these display values directly when it needs different labels or error formatting.

The API appends `display` to the typed response. The projection borrows the same result and needs no additional read or metadata request. The GUI consumes only the common result envelope and display protocol; it does not look up metric names, infer units from field IDs, choose a primary metric, or round decimal strings. Metadata remains responsible for the strategy name and documentation. Adding display fields therefore requires no field-list changes in the GUI.


`market/` separates valuation targets from typed estimators. `ValuationTarget` selects a collection, model, backdrop, model/backdrop pair or individual gift; target validation reads direct catalog keys. `TargetValuationRequest` requires an explicit strategy list. `Estimator` has an associated output type and receives `ValuationContext`; actor messages, admission and transport are outside calculation implementations. `AskFloor` reuses collection aggregates, while `ExecutionMean` and `ExecutionMedian` reuse one bounded history traversal in their report context. `StrategyValuation` keeps outputs typed, and `StrategyOutcome` isolates per-strategy failures.

`ValuationHandle::query` prepares the report in one tracked worker and pinned snapshot. A coordinator evaluates estimators together so one report cannot mix revisions or duplicate execution scans. Calculations do not require an actor per target or strategy. History is bounded to 50,000 matching observations; explicit half-open periods cannot extend into the future. Mean weights execution records equally, independently of quantity. Collection/trait estimators require three records across three identifiable gifts; individual-gift targets require three records for that gift. Observed histories do not assert complete coverage or independent sellers. Strategy metadata advertises supported target kinds and whether a period is required. The existing `gift` method and its typed composite output remain available.
