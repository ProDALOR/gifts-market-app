# market-valuation

Gift valuation contracts, actors, calculations and lifecycle ownership. Requests, strategy IDs, marks, metrics, evidence and valuation errors live here. Shared gift identities, catalog lookups and lookup failures stay in `market-gifts`. Production reads use `market-replica::ReplicaReader` and the pure `market-gifts-hub` adapter. There is no production dependency on `market-actors`, HTTP or Telegram; data actors are used only in integration tests.

`ValuationHandle::start(&arbiter, reads)` starts the gift actor on the application-selected Arbiter. `reads` is the shared `market-replica::ReadExecutor`. The application supervises the returned task and drains the shared read jobs during shutdown. The generic `Service::start_on(&arbiter, id, factory, config)` accepts a factory receiving `Lifecycle`; callers capture a `ValuationSource` or other inputs in the factory. Actors share immutable replica snapshots; they do not copy full orderbooks or create a thread per strategy.

`types.rs` owns requests and portfolio contracts; `types/report.rs` defines the unified gift report. The optional `schema` feature enables OpenAPI metadata. `gift.rs` and `gift_calculation.rs` implement `gift_floor`: collection, model, backdrop and matching model+backdrop floors; dimensionless model/backdrop multipliers; and the final mark. The final mark is `round2(min(matching floor, collection floor * unrounded multipliers))`. Only displayed multipliers and the final mark round to two decimals, using midpoint-to-even. Each metric carries a value or a typed issue. Multipliers require three eligible listing rows for both the collection and selected trait.

The gift actor retains at most eight collection/currency statistics sets, with at most 20,000 aggregate/known-trait entries per set. Statistics expire after 30 seconds or the earliest eligible ask expiry. An Actix timer refreshes the last requested scope every 30 seconds for five minutes after use. Gift resolution and all statistics are checked against one pinned view. Cache locks and scans run on read workers; the Arbiter remains responsive while work waits for capacity.

`portfolio.rs`, `floors.rs` and `calculation.rs` retain explicit quantity-based portfolio floors as a separate library capability. Each floor actor caches up to 16 normalized portfolios for 30 seconds. Relevant books and catalog references invalidate marks; unrelated updates preserve them. Name and Telegram lookups also track collection-directory changes that could introduce ambiguity. Restricted catalog rules read exact keys; unrestricted rules retain only the requested attribute while paging. Cached inputs with unchanged revisions need no worker slot. Freshness is rechecked after asynchronous validation; waiting does not renew a cached result.

`source/` owns valuation-specific catalog resolution, gift lookup, eligible asks and dependency checks. Generic bounded catalog paging belongs to `market-replica::catalog_read`, shared with data actors. `ValuationSource::prepare(callback)` returns the callback's result inside an execution result; fallible callbacks use `.await??`. Preparation pins the replica after admission. Snapshot reads, catalog loops and dependency checks cooperate with cancellation.

`ReadExecutor` shares the API/data-actor query budget and tracked jobs. Heavy preparation is limited to one worker; small metadata checks use shared admission without occupying that lane. Dropping a caller cancels its worker token, but permits remain held until blocking work exits. Shutdown rejects new reads, cancels queued work and drains admitted work. Arbitrary blocking callbacks must cooperate with their cancellation token.

`runtime.rs` contains typed messages, bounded clients, `Prepared<T>`, `Mark<T>` and lifecycle tasks. Marks contain `{strategy, data, revision, evaluated_at}`; `sync` describes the pinned source snapshot. Admission defaults to 128 queued/running requests and a 30-second caller deadline; the gift handle limits admission to 32. Dropping or timing out a caller cancels its request context. Dropping the task rejects new work and signals shutdown. Unexpected actor exit is reported by `task.run(stop)`; `task.shutdown()` waits for termination. `error.rs` maps replica failures into valuation error codes while retaining the original error as its source.

Run `CARGO_INCREMENTAL=0 cargo test --locked --offline -p market-valuation -p market-replica -p market-actors` for coverage of calculations, cache invalidation, pinned reads, bounded admission, cancellation and shutdown. Workspace dependency-boundary tests enforce the production crate direction separately from test fixtures.
