# market-telegram-bot

Gift-market application logic over `MarketDataHandle` and `ValuationHandle`. Grammers, raw updates, account/session authorization, RPCs and Telegram photo upload caching stay in `market-telegram-client`; dispatch, bounded concurrency and checkpoints stay in `market-telegram`.

`commands/parse.rs` owns menu commands and shared automatic gift detection for private, inline and guest messages. A gift URL or slug can appear alone or in a short sentence; conflicting gifts or currencies are rejected. `interactions.rs` maps private, inline, Guest Mode and callback events into common requests and holds bounded public report/pagination tokens. Gift parsing stays in `market-gifts`. User identity and response destinations come from authenticated updates, never text or callback payload fields.

`report.rs` builds one report for every entry point. Estimate strategies and formatting come from the valuation registry. Catalog names and reference floors come from existing actor/valuation reads; missing optional decoration cannot discard an estimate. One renderer builds rich HTML and its plain fallback from the same compact fields: linked title, attributes, primary estimates, selected reference floors. Reference floors and sales use compact native tables with right-aligned amounts. Estimate, floor and sale prices share exact-decimal rounding to at most two places without trailing zeros. Telegram supplies the message timestamp; the report does not repeat it. Catalog text is escaped. Calculation details, formulas, multipliers and sample counts are omitted; the title links to Telegram, while preview and share buttons provide navigation. Preview links use the same `v_` public selection codec as the GUI.

`icons.rs` owns a small semantic icon palette shared by trait names, reference floors, currencies, estimates and the sales disclosure. Defaults use ordinary emoji plus the verified cyan TON outline (`5224544724483842608`, alternative `🔻`, from `Toncoin_emoji`) for GRAM. There is no pack lookup per report. The report retains one large artwork reference; icons do not add image downloads. Artwork requests include the model document, optional symbol document and the selected backdrop palette. `market-media` combines cached first-frame SVGs with the GUI’s shared symbol positions and gradient into a 1200 × 600 PNG. The model remains centered at a 12% inset, while the native symbol wallpaper is uniformly scaled and center-cropped rather than stretched. Cover cache version 3 uses TGS source identities and both renderer versions, invalidating earlier cover keys; the native message keeps its title outside the image, so covers can be reused across gift numbers and price updates. `MarketCommands::with_report_icons` and `BotService::with_report_icons` accept optional custom emoji mappings once at construction; report callbacks retain the same shared palette. Supply verified emoji documents and their exact Telegram alternative emoji, not model animation document IDs. Rich HTML emits `<tg-emoji>` and plain fallbacks retain the alternative; the bot must be eligible to send custom emoji. No pack lookup occurs for each report.

```rust
use market_telegram_bot::{ReportIcon, ReportIcons};
use market_gifts::TelegramDocumentId;

// Supply a verified custom emoji ID and its matching alternative from your pack.
let icons = ReportIcons::default().with_custom(
    ReportIcon::Model,
    TelegramDocumentId::new(custom_emoji_id)?,
    alternative_emoji,
)?;
let service = service.with_report_icons(icons);
```

Some gift catalog media documents are themselves valid custom emoji. In the live inspection, Sakura Flower’s Gerbera document (`5289918945682288004`, alternative `🌸`, pack `SakuraFlowerSkins`) and Watching Sun document (`5546520615730544657`, alternative `🎁`, pack `PatternsEmoji2`) both contained `DocumentAttributeCustomEmoji`. These can be reused without creating or installing another pack. This is a verified example, not a rule that arbitrary gift media IDs are emoji; inspect the document attribute and use its exact alternative. Public copied packs can have different IDs for the same artwork, so pack order or display names must not establish a mapping.

The ignored client test `inspect_live_public_emoji_packs` inspects bounded explicit `MARKET_TEST_EMOJI_IDS` and `MARKET_TEST_EMOJI_PACKS` inputs and writes public metadata to `MARKET_TEST_EMOJI_OUTPUT`. It requires credentials plus an explicit `MARKET_TEST_BOT_ID` guard, uses the existing invocation scheduler and closes its temporary session; no packs are installed, created or changed. The ignored message smoke test accepts `MARKET_TEST_REPORT_ICONS`, a public JSON fixture mapping `model`/`symbol`/`gram` to `document_id` and `alternative`, to preview these mappings. The normal bot still uses its configured palette; this test does not install automatic per-gift mappings.

`history.rs` uses order-history reads independently of valuation strategies. Same-model-and-backdrop, model, backdrop and collection scopes stay explicit. A fixed half-open 30-day period and half-open ordering boundaries keep pages consistent with their selected coverage. The initial report includes one page of at most five executions in a closed native `<details>` section. Scope, pagination and retry controls stay inside that section; callbacks keep the valuation visible. Each history read has a three-second timeout, so optional history failures preserve the estimate. Further interactions read at most five executions; one browsing chain has at most ten pages. Individual sales retain their execution timestamps. Counts and lists describe observed data, not guaranteed complete Telegram sales. Ask removals never become executions.

Callbacks retain public reports through shared `Arc`s in a 256-entry LRU for 30 minutes. No authorization/session secrets or replica snapshots are retained. Restart or eviction expires controls gracefully. There are no permanent per-message subscriptions. Configure Inline and Guest Mode in BotFather, and configure the Main Mini App plus the public HTTPS origin for gift preview links. `market-app bot inspect` reports current capabilities.

Run `cargo test --locked -p market-telegram-bot -p market-telegram -p market-telegram-client`. The live-message smoke test is explicitly ignored and must only be run with authorized credentials, recipient and public valuation fixtures; ordinary tests never send Telegram messages. GUI coverage: `node web/scripts/slug-preview-browser.mjs`.

Live preview tests accept `MARKET_TEST_SESSION_DIR` to reuse an existing authorized bot session under its normal exclusive lock. Prefer it over repeated temporary bot logins, which Telegram rate-limits. Ordinary tests never authenticate or send messages.

Covers share the existing media memory/disk quotas, coalesced jobs, two renderer slots, ten-second child-process deadline and shutdown/cancellation handling. Their keys include model/symbol TGS hashes, the SVG renderer version, the cover version, shared symbol geometry and the visible palette. Cached covers are checked before SVG resolution, so retained source identities/TGS files permit PNG reuse even when SVG files were evicted. Unused symbols and tint colors are normalized out of the key. SVG and cover misses share one job-admission/render lifecycle and one disposable process runner; the assembled cover SVG is validated once in the helper. Telegram photo references are cached by the PNG content ETag, preventing cross-backdrop reuse. Unsupported/invalid covers can download a thumbnail fallback. Temporary failures and rate limits reuse only an already cached thumbnail; they never launch another download, and Retry-After is preserved. Generated PNG/SVG/TGS files stay on disk outside the repository.

For the ignored live preview, build `market-media-render` and place it beside the test executable (normally `target/debug/deps/market-media-render`). Set `MARKET_TEST_PATTERN_ID` along with the model document. `MARKET_TEST_MEDIA_DIR` can retain the disk cache across preview runs; `MARKET_TEST_COVER_OUTPUT` saves and verifies the full PNG before sending. Set `MARKET_TEST_PREPARE_ONLY=1` to inspect it without sending.
