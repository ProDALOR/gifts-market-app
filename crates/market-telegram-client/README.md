# market-telegram-client

Authenticated Telegram operations over Grammers. Owns credentials, session locking/persistence, sender connection, native gift mapping and media downloads. Update dispatch lives in `market-telegram`; market commands and presentation live in `market-telegram-bot`.

`Connection::open` requires a shared `market-invocations::Handle`. Closing a connection cancels its generation, joins the sender and drains session writes before releasing storage. The caller retains the invocation runtime across reconnects, preserving rate state. Grammers protocol maintenance, migration and update catch-up remain library-owned.

Explicit application calls use common scheduling: account concurrency, operation groups and peer gates. Inventory permits two active users with 300 ms between request starts and one active request per user. Flood waits block the account, slow-mode waits block the destination peer. Reads and idempotent configuration can retry; message retries preserve the original random ID. Bot authorization is a single attempt. SDK errors are sanitized before application handling.

`InventoryClient` is a stable capability constructed from the bot credentials, without starting a runtime or another login. The worker binds it to each connection and publishes that connection only after authentication. Disconnection clears it; old-generation cleanup cannot remove a newer connection. `page_operation(user, offset, limit)` snapshots the active generation and returns an unsubmitted operation. It reads the user's existing authenticated-session peer reference, then calls `payments.getSavedStarGifts` with all saved/unsaved/hosted gift categories included. It performs no username resolution. Invalid requests and unknown peers fail locally.

Normalized page data uses `market-gifts::inventory`; there is no transport-specific inventory collector or portfolio valuation. The application supplies page operations to `PortfolioService`, which owns pagination, coalescing and caching. Trusted callers authorize the target user before submitting requests. Credentials and access hashes stay in this crate.

Document lookups coalesce across thumbnail/TGS misses and retain bounded, short-lived references. Expired references refresh once. Transient download retries create a fresh size-bounded iterator, since Grammers consumes iterator state on RPC failure. Validation runs after releasing the invocation slot. Disk caching and HTTP serving remain in `market-media` and `market-api`.

`AccountWorker::from_file` imports the existing `accounts.json` array (`api_id`, hexadecimal `auth_key`, `dc_id`, `server_address`) into isolated in-memory user sessions. `AccountGiftResolver` implements the domain `GiftResolver` contract and calls user-only `payments.getUniqueStarGift`; it returns identity/trait facts without owner/profile data. The app owns the worker lifecycle and installs the resolver on its shared valuation service. User sessions do not replace bot authorization or bot session files. One invocation runtime survives reconnects across all imported accounts, with per-account limits and shared gift-read pacing. Same-slug requests coalesce behind a bounded cache; caller cancellation releases queued RPC work. Source exports are never rewritten. A per-key filesystem lock prevents duplicate workers in the same account data directory.

`UserLogin` handles phone/code/2FA authorization without bot credentials or a running server. Terminal prompts live in `market-app account login`; authentication calls use the invocation scheduler with no automatic replay. `AccountExports` validates and locks the destination before authorization, preserves existing records and atomically appends a compatible private export. The normal account worker only reads exports; restart it to load newly added sessions. Unsupported signup/payment flows require an official Telegram app.

`Delivery` carries an optional typed `Event`: private message, inline query, guest query or callback. Query IDs and inline message identities stay distinct from peer references. Unknown updates still carry their checkpoint. `TelegramActions::answer_callback` acknowledges a callback before application work; `send` chooses `sendMessage`, `setInlineBotResults`, `setBotGuestChatResult` or the appropriate normal/inline edit method. Rich HTML, static fallback, inline titles and typed buttons share one `Reply`; raw TL stays in the adapter. Private-only WebView markup is not used for inline/guest results. Authenticated capabilities gate share controls and choose Mini App versus website preview links.

Gift artwork asks the application-supplied `MediaCache` for a composed high-resolution cover, uploads one PNG through the shared invocation scheduler and reuses a 64-entry, five-minute photo cache keyed by image content. Covers with different model, backdrop or symbol contents never share the wrong photo. Unsupported/invalid covers may use the source thumbnail as a fallback. During temporary errors, overload or rate limits, only an already cached thumbnail is used; missing fallbacks retain the original cooldown without another download. Telegram rejects WebP as an uploaded photo, so WebP thumbnails are converted to PNG in bounded blocking work before upload; cached source bytes remain unchanged. PNG/JPEG thumbnails pass through. Conversion rejects images over 1024 × 1024 and caps decoder allocation. Upload rejection logs include the stage and Telegram RPC name without credentials. Artwork preparation has a six-second limit and cannot suppress a text/rich report. The account export and bot authorization remain separate.
