    How the stream works

    • orders.watch starts an atomic ordered-range watch. Use a fresh operation ID for each subscription, replacement or request. cancel stops requests and subscriptions without an acknowledgement. Ignore frames for canceled IDs.
    • request with method valuation.evaluate accepts the same parameters as HTTP /valuations/gift. One result or error completes the request. The server permits eight concurrent requests with a 30-second deadline. Requests fail on disconnect and are never replayed automatically. Copy request and cancellation examples from the message reference below.
    • orders.snapshot initializes range state. orders.changed applies removals and upserts atomically after checking its sequence. Use the frame-level sync for current freshness.
    • sync leaves orders unchanged. The server checks the subscribed range before sending sync.
    • Query around a row’s opaque position when changing coverage. Cancel the old subscription, use a fresh ID and replace rows atomically while preserving the scroll anchor. History uses HTTP snapshot pagination. Paused asks/bids use frozen slices via POST /orders/read.
    • Browsers answer WebSocket pings automatically. After a disconnect, reconnect with backoff and resubscribe. This console connects only on demand and closes when you leave.
    • Slow consumers close with code 1013. Error frames include an operation ID, or an empty ID for connection-level errors.
    • watch_catalog watches catalog revisions for up to eight collections. Compare catalog frames with HTTP ETag headers to reload changed choices without polling. Reconnects send the complete current revision set.
