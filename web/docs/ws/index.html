    How the stream works

    • Start with orders.watch; no preliminary query is needed. It reads up to limit rows (default and maximum 100), then watches the actual coverage returned in orders.snapshot. Use a smaller initial limit to leave room for arrivals under the 100-row live cap.
    • Snapshots contain data, range and next. Range bounds are inclusive; null means an open head or tail. Keep the returned bounds even when a boundary listing disappears. Keys are opaque and compare in ordinary ASCII order.
    • To load another page, set range.start to next and preserve the original end bound. WebSocket method orders.query and POST /orders/query share the query model. Paused views and history use finite queries with view: {kind: "snapshot"} and reuse the returned snapshot ID; release it with DELETE /orders/query.
    • A snapshot replaces subscribed state. Apply orders.changed removals and upserts atomically, checking that each sequence increases by one. Bounds stay fixed; changes do not repeat range or next. On a sequence gap or disconnect, start a fresh watch. On a capacity error, restart with narrower coverage.
    • request with method valuation.evaluate shares the HTTP /valuations/gift handler. One result or error completes a request. Requests fail on disconnect and are never replayed automatically. Copy typed command examples from the reference below.
    • market.status reports current market availability, independently of subscriptions. catalog.watch sends catalog.versions tokens matching unquoted HTTP ETag values, so only changed catalog data needs reloading.
    • Use a fresh ID for every operation. cancel stops it without acknowledgement; ignore late frames for retired IDs. Terminal error frames have an operation ID. command_error rejects a command while preserving active work. Slow consumers close with code 1013; reconnect with backoff and resubscribe. This console connects on demand and closes when you leave.
